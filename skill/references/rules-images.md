# 디자이너 원본 이미지 받기

결과물의 모든 이미지 자리에는 **디자이너가 피그마에 넣은 원본 이미지**를 넣는다. 캡처본이나 임시 자리표시 이미지로 대신하지 않는다. 피그마 임시 주소(7일 만료)를 결과물에 쓰지 않는다.

## 왜 바로 안 받아지나

- Claude 앱의 작업 공간과, 연결된 컴퓨터의 셸(device_bash VM)은 figma.com 접속이 막혀 있다 (403 / 000)
- 플러그인 API(`use_figma`)로 이미지 바이트를 읽을 수는 있지만 반환 크기가 48KB로 제한돼 원본을 옮길 수 없다
- `get_screenshot`·`node.screenshot()`은 부모 프레임 밖으로 잘린 부분을 못 담고, 글자·버튼이 겹친 이미지는 같이 찍힌다
- 그래서 **사용자 PC의 Claude 앱 내장 브라우저**로 받는다. 그 브라우저는 사용자 PC의 네트워크를 쓴다

## 순서

### 1. 원본 이미지 주소 받기

섹션 노드마다 `download_assets`를 호출해 `rawImages` 주소를 받는다 (섹션 단위로 나눠야 20개 제한에 안 걸린다).

### 2. 어느 이미지가 어느 자리인지 해시로 맞추기

`rawImages`의 순서는 노드 순서와 다를 수 있다. 추측하지 않는다.

- `use_figma`(읽기 전용)로 이미지 자리 노드의 fill `imageHash`를 읽는다. 하위 노드까지 찾고, 크기(`getSizeAsync`)도 같이 받는다
- 내장 브라우저에서 각 원본 주소를 fetch해 SHA-1을 계산한다 (`crypto.subtle.digest('SHA-1', buf)`). 피그마 `imageHash`가 원본 바이트의 SHA-1이라 앞자리가 같으면 같은 이미지다

### 3. 내장 브라우저로 내려받기

- 내장 브라우저 도구(`Claude_Browser`)를 불러오고 `https://www.figma.com` 사용 허락을 받는다 (`request_access`, scope site)
- `https://www.figma.com/robots.txt` 같은 가벼운 페이지를 열어 figma.com 출처에서 스크립트를 실행한다. 이미지 주소를 직접 열면 다운로드로 처리돼 페이지가 안 열린다
- 내장 브라우저는 파일을 받을 때마다 저장 창을 띄운다. 사용자가 싫어하므로 **파일마다 받지 않고 zip 하나로 묶어 한 번만** 받는다
    1. 원본 주소 전부를 fetch해 SHA-1을 계산하고 `window.__map[해시 앞 10자리] = 주소`로 둔다 (실제 받는 것은 필요한 해시만)
    2. JSZip을 불러온다: `eval(await (await fetch('https://cdnjs.cloudflare.com/ajax/libs/jszip/3.10.1/jszip.min.js')).text())`
    3. 필요한 해시마다 원본 바이트(blob)를 그대로 `zip.file('<해시>.<확장자>', blob)`로 넣는다 (canvas 재인코딩 없이 원본 그대로)
    4. `zip.generateAsync({type: 'blob', compression: 'STORE'})` → `<a download="images.zip">` 클릭 한 번
- 저장 창이 떠도 **사용자에게 저장을 부탁하지 않는다.** 파일은 이미 다운로드 폴더에 `.tmp`(GUID 이름)로 받아져 있다. 바로 stage한 뒤에 "저장 창은 취소해도 된다"고 한 줄로 알린다 (취소하면 `.tmp`가 지워질 수 있으므로 stage가 먼저)
- 받기 전에 "저장 창이 한 번 뜨는데 취소하시면 된다"고 미리 알린다

### 4. 꺼내서 정리하기

- 다운로드 폴더 접근을 요청한다
- 가장 최근 `.tmp`(zip)를 작업 공간으로 가져와(stage) 풀고, 파일 이름(해시)으로 2번의 대조 결과대로 `assets/images/<id>/<용도>-<번호>.jpg`로 저장한다 (투명도 있으면 PNG, 없으면 JPEG 86 · progressive. 긴 변은 표시 크기의 2배 정도로 줄인다: 전체 폭 2400, 나머지 1600)
- 다 쓰면 다운로드 폴더의 `.tmp`를 지운다 (삭제 권한 요청)

## 예외

- **영상 fill**(`fills[].type === 'VIDEO'`)은 파일로 꺼낼 수 없다. 같은 섹션 `rawImages`에 있는 원본 프레임을 `poster`로 걸고, 영상 파일은 사용자에게 받아야 한다고 알린다
- **아이콘·핀·로고 등 벡터**는 `download_assets`의 `svgAssets` 주소를 내장 브라우저에서 fetch해 텍스트로 받아 `.svg` 파일로 저장한다. CSS로 비슷하게 다시 그리지 않는다
- 장식 패턴처럼 벡터가 수십 개 겹친 그래픽은 `get_screenshot`으로 한 장 받는다 (1024px로 줄어드므로 원본 교체가 필요하다고 알린다)
- 디자인에 이미지가 없는 자리는 `src` 없는 `<img>`로 두고, 비어 있으면 상자가 보이지 않게 한다 (`:has(img:not([src]))`)
- 레이어명에 `Adobe Stock preview` 등이 있으면 워터마크 미리보기라 실서비스 전 원본 교체가 필요하다고 알린다

## 위 방법이 안 될 때

내장 브라우저가 없거나 PC가 연결돼 있지 않으면 **Export 목록**을 만든다: 저장할 파일명 · 피그마 레이어명 · 권장 형식 · 배율. 사용자가 그대로 내보내 폴더에 넣으면 이어간다. Claude Code로 사용자 PC에서 실행 중이면 `curl -fL`로 바로 받는다.
