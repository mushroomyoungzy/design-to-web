# 디자인 → 웹 퍼블리싱 (작업 순서)

피그마 링크 · JPG 시안 · 기존 HTML 중 하나를 받아 **입력 받기 → 분석 → 확인 → 퍼블리싱 → 검수 → 미리보기** 순서로 진행한다.
결과물은 HTML · SCSS · jQuery로 된 단독 페이지이고, 사용자가 HTML과 CSS만 떼어 다른 사이트(CMS)에 옮겨 쓸 수 있어야 한다.

대화는 한국어 존댓말로 한다. 자음만 쓰지 않는다. 진행 중 설명은 짧게, 결과는 무엇이 바뀌었는지만 말한다.

## 함께 읽을 파일

작업을 시작하면 `<규칙 폴더>`(최신 규칙을 받아 온 폴더, 설치된 스킬의 SKILL.md가 정한다)의 아래 파일을 **모두** 읽는다.

| 파일 | 내용 |
|---|---|
| `references/rules-design-input.md` | 입력별(피그마 / JPG / HTML) 읽는 법, 프레임·주석·도형 해석 |
| `references/rules-images.md` | 디자이너 원본 이미지를 받는 법 (PC 브라우저 경유, 해시 대조) |
| `references/rules-markup.md` | 이름 규칙(BEM·id·훅), 시맨틱, 제목 단계, 마크업 순서, 접근성, 이미지, JS, 파일 편집 |
| `references/rules-scss.md` | SCSS 파일 구조, `#<id>` 감싸기, `px-rem`·`font-resize`, 4의 배수, 속성 순서, 미디어쿼리, 분기점 |
| `references/rules-interaction.md` | 슬라이더 드래그, 호버와 태블릿, 그림자 잘림, 쌓일 때 정렬 등 기본 동작 규칙 |
| `references/rules-medical-ad.md` | 병의원 사이트일 때만 |

`<스킬 폴더>/template/`(설치된 스킬 안)은 결과 폴더의 뼈대, `<규칙 폴더>/scripts/build_preview.py`는 Claude 앱 미리보기용 묶음, `<규칙 폴더>/scripts/check_layout.js`는 자동 검사 스크립트다.

## 모드 고르기 (맨 처음)

쓰는 사람에 따라 과정을 줄인다. 입력(링크·파일)을 받으면 한 문장으로 무엇을 할지 알리고, 누가 무엇을 보려는지 AskUserQuestion으로 하나만 묻는다. 사용자가 처음부터 "코드", "퍼블리싱", 저장 위치를 말했으면 묻지 않고 개발 모드.

| 모드 | 이런 사람 | 묻는 것 | 건너뛰는 것 | 주는 것 |
|---|---|---|---|---|
| **미리보기** (기획) | 회의·공유용으로 웹에서 클릭되는 화면이 필요 | 없음 | 저장 위치·폴더·id 질문, 분석 리포트, 확인 단계 | 미리보기 링크 |
| **시안 확인** (디자인) | 시안이 웹에서, 분기점마다 어떻게 보이는지 확인 | 없음 | 위와 같음 | 미리보기 링크 + 1920 · 1024 · 390 화면 캡처 한 장 + 디자인에서 확인할 점(잘리는 글자, 분기점에서 어색한 곳, 오타) |
| **개발** (퍼블·개발) | 규칙대로 된 코드가 필요 | 아래 0번 세 가지 | 없음 | 지금까지대로 전부 |

미리보기·시안 확인 모드:
- 페이지 id는 프레임 이름(없으면 사이트 이름)을 영문 snake_case로 직접 정하고, 결과 끝에 알려 준다
- 저장은 PC 폴더 대신 zip(SendUserFile)으로 준다. 사용자가 PC 폴더를 말하면 그때 저장한다
- 분석 리포트는 만들지 않고, "확인 필요"였을 내용은 결과 끝에 짧게 목록으로 적는다
- 움직임은 일반적인 슬라이드·페이드, 반응형은 규칙 기준, 기능(문의·검색 등)은 더미
- 코드는 개발 모드와 똑같은 규칙으로 만든다 (나중에 개발자가 그대로 이어받을 수 있게). 검수(5번)도 똑같이 한다
- 대화에서 SCSS·BEM·커밋 같은 개발 용어를 쓰지 않는다. "화면", "링크", "캡처", "파일" 정도로 말한다
- 디자이너 원본 이미지를 못 받으면 빈 자리로 두고, 어떤 이미지가 필요한지 결과 끝에 적는다

## 0. 입력 받기 (개발 모드: 아무것도 정하지 말고 먼저 묻는다)

시작하면 한 문장으로 무엇을 할지 알리고, 아래 세 가지를 **사용자에게 직접 입력받는다.** 제안값을 골라주지 말고, 사용자가 정할 때까지 진행하지 않는다.

1. **입력**: 피그마 링크 / JPG·PNG 시안 / 기존 HTML 중 무엇인지, 그리고 그 링크나 파일
2. **저장 위치**: 결과물을 저장할 PC 폴더 경로 (예: `D:\project`, 바탕화면)
3. **폴더 이름**: 그 안에 만들 작업 폴더 이름

값을 직접 써야 하는 항목은 선택지(AskUserQuestion)로 묻지 않는다. 선택지를 고르면 값 입력 칸이 비기 때문이다. 메시지로 "아래 세 가지를 알려주세요" 형태로 묻는다.

받은 뒤:
- 작업 목록(TaskCreate)을 만든다
- 피그마 링크면 피그마 커넥터 연결을 확인한다. 파일이 안 열리면 `whoami`로 연결된 계정을 확인하고, 그 계정에 파일 공유(보기 권한) 또는 커넥터를 다른 계정으로 다시 연결하도록 안내한다
- **PC 폴더 연결**: Claude 앱이 사용자 컴퓨터에 연결돼 있으면(remote-devices 도구) 저장 위치 폴더 접근을 요청하고 작업 폴더를 만든다. Claude Code로 사용자 PC에서 실행 중이면 그 경로에 바로 만든다. 둘 다 안 되면 작업 공간에서 만들고 마지막에 zip으로 전달한다고 알린다
- 결과는 작업 공간에서 만들고, 단계마다 PC 폴더로 저장(commit)한다. 덮어쓰기 전에 PC 파일이 마지막 저장본과 같은지(md5) 확인해 사용자가 고친 내용을 지우지 않는다

결과 폴더 구조:

```
<저장 위치>/<폴더 이름>/
├── index.html                 미리보기 겸 결과 마크업
├── report.html                분석 리포트
├── <id>_spec.md               분석 리포트 텍스트판
└── assets/
    ├── css/
    │   ├── appearance/        color.css · root.css · layout.css (사이트 공통값)
    │   ├── base.css           reset · typography · common (사이트 공통값)
    │   ├── <id>.css           컴파일 결과 ← 떼어 갈 파일
    │   └── scss/
    │       ├── abstracts/     _variables · _mixins
    │       ├── base/ layout/
    │       ├── base.scss
    │       └── <id>.scss      페이지 스타일 ← 떼어 갈 파일
    └── images/<id>/           ← 떼어 갈 이미지
```

## 1. 분석

`references/rules-design-input.md`의 입력별 절차대로 읽는다.

- 피그마: 페이지 목록 → 링크한 노드가 있는 페이지 전체 프레임 → 변수 → 댓글 → 스크린샷 → **섹션마다 design context**
- **주석·댓글·레이어 이름 속 동작 설명과 참고 링크는 반드시 모두 확인한다.** 링크는 내장 브라우저로 직접 열어 움직임을 본다 (`rules-design-input.md`의 주석·레퍼런스)
- 페이지 전체 metadata는 하위 레이어가 빠질 수 있다. 섹션 구조·텍스트·이미지 유무는 반드시 섹션별 design context로 확인한 뒤에 판단한다 ("글자까지 이미지" 같은 판단을 metadata만 보고 내리지 않는다)
- JPG: 섹션을 잘라 보며 구조·수치 추정
- HTML: 화면 유지 / 반응형으로 새로 짜기 중 무엇인지 먼저 묻고, data URI를 뺀 사본으로 코드 전체 읽기 + 렌더 스크린샷 (`rules-design-input.md`의 HTML 절차)

## 2. 분석 리포트 (개발 모드)

`<스킬 폴더>/template/report.html`을 채워 `report.html`로 만든다. `{{...}}` 자리를 채우고, 예시 행은 필요한 만큼 복제하며, 쓸 내용이 없는 섹션은 지운다. 스크린샷은 data URI로 넣는다.

- 한눈에 / 프레임 구성 / 디자인 토큰(색 스와치·폰트·텍스트 스타일) / 섹션별 분석 / 공통 컴포넌트 / 주석·댓글 / 이미지 목록 / 정해진 것 / 확인 필요 / 진행 순서
- 디자인의 오타, 의료광고 금지 표현, 워터마크 미리보기 이미지(레이어명에 `Adobe Stock preview` 등)를 찾아 적는다

보여주기: 아티팩트로 게시해 Claude 앱에서 바로 보이게 하고, 같은 파일을 PC 폴더에 저장한다. 같은 내용을 `<id>_spec.md`로도 저장한다.

## 3. 확인 받기 (개발 모드: 퍼블리싱 전에 반드시)

리포트의 "확인 필요"를 묻는다. 고르는 항목(페이지 id 후보, 문구 수정 여부 등)은 AskUserQuestion, 값을 써야 하는 항목은 메시지로.

- 페이지 id (snake_case)
- 범위: 링크한 페이지만 / 다른 페이지 포함
- 모션 가이드를 줄 섹션
- 오타·금지 표현 수정 여부, 디자인에 없는 카피

따로 말이 없을 때 기본값:
- 움직임 디테일은 사용자 가이드 → 없으면 주석의 참고 URL → 없으면 일반적인 슬라이드·페이드
- 반응형 시안이 없으면 `rules-scss.md` 분기점과 `rules-interaction.md` 기준으로 구현
- 탭 필터·더보기·문의·링크 등 기능은 더미

## 4. 퍼블리싱

1. `<스킬 폴더>/template/`을 작업 폴더로 복사한다 (`report.html`은 이미 만든 것을 둔다)
    - `index.html`의 `{{PAGE_ID}}`, `{{PAGE_TITLE}}`, `{{SITE_NAME}}`을 채운다
    - `scss/_page-template.scss`를 `<id>.scss`로 복사하고 `#page_id`를 `#<id>`로 바꾼다. 템플릿 원본은 지운다
    - 디자인에 헤더·푸터가 있으면 `#<id>`가 헤더·main·푸터를 모두 감싸게 한다
2. 색 토큰: `appearance/color.css` 값을 디자인 색으로 바꾸고, 없는 색은 `scss/base/_root.scss`에 추가 후 `base.css` 재컴파일. 컨테이너 폭은 `appearance/root.css`의 `--inner-width`(컨테이너 + 40)
3. 디자인에서 쓰는 폰트 중 Pretendard 외 영문 폰트(예: Playfair Display)는 `index.html` head에 Google Fonts로 추가한다
4. 이미지는 `references/rules-images.md`대로 원본을 받아 넣는다. 받기 전까지는 `src` 없는 `<img>`
5. 공통 → 섹션 순서로 하나씩: 마크업 → SCSS → 컴파일(`npx sass@1 --no-source-map assets/css/scss/<id>.scss assets/css/<id>.css`) → 점검표
6. 인터랙션은 `index.html` 맨 아래 인라인 `<script>`에 jQuery로. `rules-interaction.md`의 기본 동작(드래그 등)을 모두 넣는다
7. 반응형
8. 파일은 처음 만들 때 한 번만 통째로 쓰고, 이후에는 부분 치환만 한다

섹션 점검표:
- [ ] 마크업에 유틸리티 클래스가 없다. 모든 요소가 BEM. `__` 훅 클래스에는 스타일이 없다
- [ ] 모든 선택자가 `#<id>` 안에 있고, 쓴 공통 클래스(`.inner`, `.sr-only`, `button` 리셋)가 그 안에 정의되어 있다
- [ ] `px-rem()` 값이 4의 배수, 글자 크기는 `font-resize`, SCSS에 주석 없음
- [ ] 속성 순서, 미디어쿼리가 선택자 안에서 속성 뒤에 있음
- [ ] 호버가 `@media (hover: hover)` 안에서 `:focus`와 `:hover`를 함께
- [ ] 제목이 h3부터, 버튼·컨트롤이 콘텐츠 뒤에 마크업
- [ ] 이미지 자리마다 디자이너 원본 이미지와 alt, 아이콘 버튼에 sr-only 문구
- [ ] 전화번호·이메일에 `tel:`·`mailto:` 링크가 걸려 있다 (헤더·푸터 포함)
- [ ] 디자인의 아이콘·핀·로고는 SVG 원본을 받아 쓴다. 비슷하게 새로 그리지 않는다
- [ ] 이 섹션에 달린 댓글·주석·레이어 이름 속 동작 설명과 참고 링크를 확인해 반영했다
- [ ] 병의원 사이트면 금지 표현 없음

## 5. 검수

작업 공간의 Playwright로 한다.

1. **자동 검사**: `node <규칙 폴더>/scripts/check_layout.js <작업 폴더>/index.html`
   - 1920 · 1600 · 1440 · 1281 · 1280 · 1024 · 800 · 640 · 445 · 390 · 360 폭마다 가로 스크롤, 깨진 이미지, 스크립트 에러, **잘린 탭·버튼·글자**를 찾는다
   - 폰트·jQuery CDN은 npm으로 받아 로컬로 바꿔 끼운다 (처음 한 번 설치)
   - 일부러 넘치게 만든 영역(마퀴, 슬라이더 트랙)은 감싸는 요소에 훅 클래스 `__overflow`를 붙여 둔다
   - "모든 폭에서 문제 없음"이 나올 때까지 고친다
2. **눈으로 비교**: 1920 폭 섹션별 스크린샷을 피그마 섹션 스크린샷(또는 원본 HTML 렌더)과 나란히 비교 (위치·크기·색·간격)
3. **전체 스크린샷**: 1280 · 1024 · 800 · 390 전체 페이지를 몇 장씩 이어 붙여 깨진 곳 확인. 자동 검사는 잘림만 찾으므로 어색한 배치·빈 공간은 여기서 본다
4. **동작**: 슬라이더 드래그, 탭 클릭, 메뉴 열기, 아코디언을 스크립트로 눌러 상태가 바뀌는지 확인
5. 고친 뒤 PC 폴더에 다시 저장

## 6. Claude 앱 미리보기

검수가 끝나면 Claude 앱에서 바로 볼 수 있게 아티팩트로 게시한다.

```
python3 <규칙 폴더>/scripts/build_preview.py <작업 폴더> <미리보기 폴더> "<제목>"
```

- 스크립트가 미리보기 폴더를 만들고, 아티팩트에서 막히는 외부 CSS(Pretendard, boxicons)를 npm에서 받은 로컬 폰트로 바꾸고, `files.json`(게시할 파일 목록)을 출력한다
- Artifact 도구로 `<미리보기 폴더>/index.html`을 `root`=미리보기 폴더, `files`=`files.json` 내용으로 게시한다
- 이후 수정할 때마다 PC 폴더 저장과 미리보기 재게시를 같이 한다 (같은 파일 경로로 게시하면 같은 링크가 유지된다)
- 바탕화면 결과물은 원래대로 CDN을 쓴다. 로컬 폰트는 미리보기에만 넣는다

## 마무리

- 결과 폴더 위치, 한두 줄 요약, 남은 확인 사항만 알린다
- 떼어 갈 파일을 짚어 준다: `index.html`의 `#<id>` 블록, `assets/css/<id>.css`(또는 `.scss`), `assets/images/<id>/`
- 작업 중 만든 임시 파일(다운로드 폴더의 임시 파일, `_raw` 등)은 사용자에게 묻지 말고 지운다. 삭제 권한이 없으면 삭제 권한을 요청한다
- 진행한 단계를 다시 늘어놓지 않는다
